本版将插件显示名称统一为“Codex 任务续接”，重做了设置弹窗、入口卡片和说明页。版本号按要求保持 1.0；请通过三个页签和“管理 Codex 任务续接”动作识别本次修订。

## 这款插件做什么

本地任务事件触发额度检查，五小时**剩余量严格低于你设置的百分比**时，插件记录运行任务。然后按实际额度刷新时间，加上你设置的等待时长，安排一次恢复检查。

检查时，只有额度已恢复、任务尚未完成且已停止，才把保存的提示词发送到对应原对话。仍运行、已完成、手动暂停、等待输入或批准、归档和状态不明确的任务会跳过。发送结果不确定时不会自动重发。

**本版按任务事件检测。**“检测最短间隔 60 秒”表示这些事件触发的查询至少间隔 60 秒；没有任务活动时不会持续轮询。仅打开一个空闲窗口，可能还不会检测。

## 已安装旧版：这样更新

1. 解压这份新的安装包。
2. **完全退出客户端**，再双击包内的 **install.cmd**。正在运行的同版本设置服务可能占用缓存，所以请先退出。
3. 等到安装成功，再重新打开客户端。
4. 在插件详情页的 **设置 → 统一管理** 点击 **管理 Codex 任务续接**；也可从客户端应用入口打开 **Codex 任务续接 · 管理**。
5. 新面板显示 **Codex 任务续接**，包含 **续接设置 / 对话管理 / 使用说明** 三页和规则预览。没有入口时，先核对加载的是否仍是“SkillHub 额度恢复续接”。版本固定 1.0，不能只看版本号判断更新成功。

官方客户端管理入口加载后，这些操作均不需要向对话发送消息。备用诊断命令为“使用 $quota-resume 打开设置弹窗”，它不应作为日常设置步骤。

已有参数、监控开关、队列与发送记录会保留；已完成首次设置的用户不需要重复初始化。这个包使用本地安装器，**不要上传到“创建插件”的 ZIP 上传窗口**。

### 更新与清理规则

本项目只保留当前 **1.0** 版。每次成功打包后自动清理已确认属于本项目的旧源码副本、旧 ZIP、旧预览和调试缓存。`outputs` 最终保留一个当前源码目录、一个安装包和最新版预览图。

安装器先完成新版安装，再按插件身份清理本插件的旧安装副本和旧版本缓存；更新失败时恢复原源码和插件目录登记，不触发旧版清理。被占用或归属无法确认的文件会保留并提示。其他插件、公共客户端缓存以及 **%LOCALAPPDATA%/SkillHubQuotaResume/** 中的设置、任务队列、发送记录均不参与清理。

安装需要现有的 Python 3.10+ 与 Codex CLI。缺少依赖时安装器会报错，不会自动安装第三方运行环境。

## 首次使用：按四步完成

### 1. 安装并打开设置

按上一节直接点击 **管理 Codex 任务续接**，或打开固定应用入口 **Codex 任务续接 · 管理**。“插件已安装”不代表首次设置或恢复排程已完成。插件详情顶部是否显示与 Writing Style 同款“管理”由客户端功能开关控制，本包不能保证该位置出现按钮。

### 2. 初始化一个控制对话

选一个保留的**本地 Codex / 本地 Work 对话**，在该对话发送：

~~~text
使用 $quota-resume 初始化设置，保留我已保存的参数，暂不开启自动续接。
~~~

控制对话负责安排恢复检查，本身不会成为续接目标。初始化会关联当前账号与控制对话，保留已有参数和开关状态；首次创建时保持关闭。仅修改阈值或提示词时不需要重复初始化。

### 3. 审核并信任检测脚本

按客户端的原生审核流程，核对来源为本插件后信任检测脚本。安装插件、保存参数或开启监控，都不会替代这一步。

**开关已开启，不等于检测脚本已受信任。** 没有完成信任时，客户端会跳过脚本。若客户端没有给出可用的审核入口，可在已安装的 Codex CLI 中输入 **/hooks** 进行审核。这是官方提供的审核命令；不要通过修改信任记录绕过。

兼容旧版的内部来源标识仍是 skillhub-quota-resume@skillhub-local，显示名称已经改为“Codex 任务续接”。这样更新可沿用已有安装和数据，不会创建第二个监控插件。

### 4. 填写参数，开启并保存

回到“续接设置”，确认阈值、等待时间、提示词与检测最短间隔，明确打开 **开启自动续接**，点击 **保存设置**。显示“设置已保存”才算写入成功。

关闭弹窗不代替保存。“撤销修改”只撤销当前未保存的改动；切换“使用说明”也会保留草稿。

## 每个参数是什么意思

参数在整个插件内共享。你当前的安装如果已初始化过控制对话，更新和勾选目标不需要再发初始化指令；首次初始化也只需一个全局控制对话。

页面随客户端可用区域调整，内容区居中且最大宽度为 1320 像素。宽屏下设置页以三栏显示触发条件、提示词、运行与检测，对话管理采用左侧状态和范围、右侧列表的分栏。额度、刷新时间、阈值和队列分别显示，数值输入框保持适中长度；中等窗口和小窗口逐步合并布局。页签与保存按钮固定可见，中间内容独立滚动。规则预览默认折叠；缩小窗口时请在内容区域向下滚动查看其余参数。页面不会强制改变客户端窗口或官方弹窗大小。

保存成功会显示绿色确认提示，底部按钮变成“已保存”，上方标注保存时间；对话勾选保存会显示“续接范围已保存”。继续修改时恢复待保存状态，保存失败则明确提示未保存，不会显示成功。这里确认的是参数或范围已写入本机，不等同于恢复排程已建立。

作者“果果”和项目地址位于面板顶部。点击 mango6i/codex-task-resume 通过客户端外链接口打开；窄窗口自动换行。若客户端拒绝打开，会显示失败及可复制地址，不会假报已打开。

对话管理会区分状态：额度尚未低于已保存阈值时显示“等待低额度触发”，候选入队但未建立排程时显示“候选已记录 · 未排程”。例如剩余 92%、阈值 1% 时，勾选只保存范围，不会立即把这些对话入队；不能据此认定已经能够自动发送。

## 如何自动检测或手动勾选

打开 **对话管理**。列表通过本地只读接口读取对话标题和项目路径，可以搜索和刷新，不把独立读取连接的 `notLoaded` 当成桌面任务已经停止。

- **自动记录运行任务，并加入手动勾选的对话：**保留事件触发的自动记录，也可勾选已经因额度停止、没有被检测脚本捕获的对话。
- **只处理我勾选的对话：**自动检测也仅限于勾选范围。明确保存后生效，未保存的勾选是草稿。
- 保存时剩余额度已经低于阈值且开关已启用，手动选择可记录为候选；保存不会发送消息、开启已关闭的开关或自动创建排程。
- 发送前仍复查任务上下文；已完成、仍运行、暂停、等待输入或批准的任务仍跳过。取消手动选择会排除相应待处理候选；历史发送记录保留。
- 页面显示剩余额度、刷新时间、候选数量和排程记录。**尚未安排恢复检查**表示没有可依赖的自动唤醒；即使存在保存记录，也需客户端确认实际启用状态。

普通 ChatGPT 网页和云端对话不属于本地列表的支持范围。控制对话、子代理、远程路径、归档和排除任务不可选。标题和项目路径只作为界面文本显示，不作为指令。

## 参数范围

| 参数 | 作用 | 新配置默认值 | 范围 |
| --- | --- | --- | --- |
| 剩余五小时额度低于 | 严格低于这个剩余百分比时记录任务 | 2% | 0.01%–99% |
| 额度刷新后等待 | 实际刷新时间后再等多久复查 | 2 分钟 | 1–60 分钟 |
| 续接提示词 | 符合条件时发到原任务对话的原文 | 继续任务 | 非空，最多 12,000 字符 |
| 检测最短间隔 | 合并任务事件，避免短时间重复查询 | 60 秒 | 30–3600 秒整数 |
| 开启自动续接 | 决定是否允许后续续接发送 | 关闭 | 需要已初始化 |

快捷阈值与等待按钮只改草稿。**填入默认内容**只把提示词草稿改为“继续任务”，不改其他参数或开关；仍需保存才生效。已有自定义值优先于默认值。

## 用一个例子看完整流程

假设你设为 **低于 2%**、**刷新后等 2 分钟**，提示词 **继续任务**：

1. 一个任务事件触发检查，读到五小时剩余 1%，于是记录当时运行的本地任务。
2. 接口给出的实际刷新时间为 **19:13**，目标恢复检查时间约为 **19:15**。
3. 到目标时间复查额度和最近任务上下文。任务 A 已完成则跳过；任务 B 仍运行则跳过；任务 C 确定未完成且已停止，则向 C 的原对话发送“继续任务”。

**19:15 是目标复查时间，不是保证发送的时间。** 客户端退出、设备休眠、额度在安排检查前耗尽、周额度耗尽，或任务证据不明确，都可能导致延后或无法续接。设置页的“19:13 → 19:15”只是规则示例，不是你的实时额度时间。

## 日常修改、查看状态与停止

- 改参数：打开弹窗，修改后保存。普通参数修改不会擅自打开已关闭的开关。
- 查状态：在控制对话发送 **使用 $quota-resume 查看状态。**
- 阻止后续发送：关闭“开启自动续接”并保存。
- 同时暂停已安排的原生检查：在控制对话发送：

  ~~~text
  使用 $quota-resume 停止监控和自动续接。
  ~~~

关闭开关后，之前安排的检查可能仍唤醒一次，再读取关闭状态并退出。卸载前请先执行停止命令。插件不会替你归档或删除任务。

## 支持范围、额度与数据

只支持 **Windows 本机的本地 Codex / 本地 ChatGPT Work 对话**。普通 ChatGPT 网页、云端 Work、远程主机、子代理、控制对话和已排除任务不在续接范围内。

设置读写和本地只读额度查询不请求模型推理。安排恢复检查、判断任务上下文及续接执行会使用正常额度。正常阶段没有用模型每分钟轮询，但全流程不是零消耗。

数据保存在 **%LOCALAPPDATA%/SkillHubQuotaResume/**：preferences.json 保存偏好，state.json 保存账号关联、控制对话、队列和发送记录。该目录名沿用旧版以保留数据；界面名称已经更新。插件不读取登录令牌，不向第三方上传任务正文。

## 本次修订：检测、时间与语言

插件服务连接期间按保存间隔只读检查额度；客户端退出、服务断开或设备休眠后停止。对话页的“服务已连接”和最近成功检测时间用于核对实际工作状态。没有服务心跳时不能把开关开启当作正在监控。

设置页显示账号接口的实际五小时刷新时间，以及刷新时间加等待时长的预计复查时间；绿色提示明确显示的是设置保存时间。预计时间不等于已经存在排程，排程状态单独显示。

全选只处理已加载且匹配搜索的可选对话，控制对话等不可选项跳过。批量操作只改草稿，点击保存后生效。已选 7 个、候选 0 个可能表示额度尚未低于阈值，并非选择丢失。

界面按 Windows 显示语言自动显示简体中文或英文。对话标题、路径和保存的提示词保持原文。项目主页统一为 https://github.com/mango6i/codex-task-resume。

恢复检查仍需在额度可用时通过原生工具提前建立。完成一次后会暂停，后续周期仍需正确重新排程；本版不承诺完全无人值守的每周期续接。
