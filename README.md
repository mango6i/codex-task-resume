# Codex 任务续接

**集中管理本地任务，在额度恢复后续接符合条件的未完成对话。**

适用于 Windows 本地 Codex / ChatGPT Work。支持自定义额度阈值、等待时间和续接提示词，以及本地对话选择。

[下载安装包](https://github.com/mango6i/codex-task-resume/releases) · [安装指南](docs/INSTALL.md) · [让 GPT 帮你安装](docs/INSTALL_WITH_CODEX.md) · [反馈问题](https://github.com/mango6i/codex-task-resume/issues)

版本 **1.0 · 预览版** · 作者 [果果](https://github.com/mango6i) · [MIT License](LICENSE)

> **使用前请了解：**恢复检查需要提前建立原生排程。如果额度耗尽时尚未建立排程，无法保证自动唤醒。完整的额度耗尽、刷新、唤醒与发送周期仍待验证，后续额度周期也需正确重新排程。

## 功能

- **统一设置**：保存一次即可管理阈值、刷新后的等待时长和多行提示词。
- **切换账号后自行绑定**：点击顶部额度栏的“绑定当前账号”，自动备份旧状态、保留参数和选择范围；旧候选不带到新账号，发送记录保留。绑定后再明确开启自动续接。
- **低额度才排程**：只有严格低于保存的阈值并记录到实际运行任务时，才准备本轮恢复检查。额度充足或恰好等于阈值时，不建立空检查。
- **本地额度检测**：插件服务连接期间只读查询额度，空闲时也可检测，不使用模型每分钟轮询。
- **实际刷新时间**：显示账号接口返回的五小时额度刷新时间，以及加上等待时长后的预计复查时间。
- **对话管理**：搜索、刷新、勾选、全选当前列表及清空选择；暂不可读的历史选择不会阻塞其他选择保存，也不会因此入队。
- **清楚的状态**：分开显示已选对话、候选数量、最近检测、任务事件及排程记录。
- **快速续接**：只查询已记录对话的原生状态与“额度已用尽”错误，不读取项目上下文或遍历全部对话；跳过已完成任务，按保存原文发送，并保留防重复记录。

## 安装

需要 **Windows、Python 3.10+**，以及支持本地插件的 Codex / ChatGPT Work 客户端。安装器会自动查找客户端附带或单独安装的 Codex CLI，无需手动修改 PATH。

1. 从 [Releases](https://github.com/mango6i/codex-task-resume/releases) 下载 `codex-task-resume-1.0.zip` 并解压。
2. 完全退出客户端，运行解压目录中的 `install.cmd`。
3. 安装成功后重新打开客户端。
4. 在插件详情的 **设置 → 统一管理** 中点击 **管理 Codex 任务续接**，或使用应用入口 **Codex 任务续接 · 管理**。

也可以把 ZIP 附给能访问本机文件的本地 Codex / ChatGPT Work，使用[安装提示词](docs/INSTALL_WITH_CODEX.md)。这个包使用本地安装器；GitHub 自动生成的 Source code 压缩包与发行安装包不同。

## 快速使用

1. 在一个保留的本地控制对话中初始化一次：

   ```text
   使用 $quota-resume 初始化设置，保留我已保存的参数，暂不开启自动续接。
   ```

2. 按客户端原生提示审核并信任插件的检测脚本。
3. 在设置面板中填写参数，明确开启自动续接并保存。
4. 在对话管理中选择范围和目标，点击 **保存选择**。
5. 受监控任务实际运行且剩余额度严格低于阈值时，检测脚本记录该轮任务并请求一次原生恢复检查；确认客户端已信任脚本且排程已启用。

参数和目标都在面板中统一修改，不需要在每个目标对话重复初始化。

已建立的原生恢复排程在后台执行，无需把控制对话置于前台，也无需打开管理面板。控制对话仍需保留，客户端和设备仍需运行。只有低额度时记录到的任务才会请求排程，恢复检查由控制对话自动执行；后台只读服务本身不能建立排程或发送消息。若额度在排程成功前已耗尽，仍无法保证自动唤醒。

## 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 剩余额度阈值 | 2% | 五小时额度严格低于此值时记录候选；范围 0.01–99% |
| 刷新后等待 | 2 分钟 | 实际刷新时间之后等待再复查；范围 1–60 分钟 |
| 续接提示词 | `继续任务` | 按保存的原文发送，保留换行 |
| 检测最短间隔 | 60 秒 | 插件服务与任务事件共用查询节流 |
| 自动续接 | 关闭 | 初始化并审核脚本后，由用户明确开启 |

例如，实际刷新时间为 19:13，等待 2 分钟，19:15 起才允许恢复检查。原生排程可能延后唤醒，只有核验其启用状态、控制对话和实际唤醒时间后才算挂载成功；显示排程卡片不代表已经启用。绿色确认中的时间是设置保存时间。

## 常见问题

**切换账号后提示重新关联，在哪里操作？** 打开插件的“续接设置”，点击顶部“刷新额度”旁边的 **绑定当前账号**。成功后开启“自动续接”并保存设置。无需在对话里重新发初始化指令；重复点击当前已绑定账号不会关闭监控或清空记录。

**已选多个对话，为什么候选仍为 0？** 选择仅限定允许处理的范围，不会直接入队或启动对话。只有本轮低额度时实际运行、并被绑定具体任务轮次的工作才会记录。候选与已建立的排程也分别显示。

**“回合已结束”是否表示任务完成？** 这里只表示最近一次任务事件。发送前只查询记录中对话的原生轮次状态和额度错误，不读取上下文；完成、仍运行、暂停、等待输入或批准、归档及状态不明的任务会跳过。

**刷新额度失败怎么办？** 查询会重试一次。若有近期成功数据，会明确标注为历史数据；否则显示暂未获取，可稍后重试。历史显示不会作为发送依据。

**是否消耗额度？** 设置读写与本地只读额度查询不调用模型；建立排程、恢复检查和继续执行任务使用正常额度。

**客户端关闭后还能运行吗？** 插件服务断开或设备休眠后无法继续本地检测，恢复执行可能延后。普通 ChatGPT 网页、云端任务、远程主机及子代理不受支持。

**客户端更新会影响使用吗？** 可能影响 Hook、界面资源或原生排程接口。更新插件后重启客户端，并按提示检查脚本信任。请同时核对候选数量和已核验的恢复排程；开关开启不代表排程已经建立。当前版本兼容旧界面入口，停止事件不会额外创建继续轮次。

**如何停止？** 关闭自动续接开关并保存。要同时暂停已建立的检查，在控制对话发送：`使用 $quota-resume 停止监控和自动续接。`

## 数据与隐私

设置和运行记录保存在本机 `%LOCALAPPDATA%/SkillHubQuotaResume/`。更新保留已有设置、选择、队列和发送记录。源码与发行包不包含实际用户设置、账号关联、任务队列或私人对话。

这是第三方本地插件。界面截图使用示例数据；反馈问题时请遮住个人对话、路径和账号信息。
