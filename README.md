# Codex 任务续接

**集中管理本地任务，在额度恢复后续接符合条件的未完成对话。**

适用于 Windows 本地 Codex / ChatGPT Work。支持自定义额度阈值、等待时间和续接提示词，以及本地对话选择。

[下载安装包](https://github.com/mango6i/codex-task-resume/releases) · [安装指南](docs/INSTALL.md) · [让 GPT 帮你安装](docs/INSTALL_WITH_CODEX.md) · [反馈问题](https://github.com/mango6i/codex-task-resume/issues)

版本 **1.0 · 预览版** · 作者 [果果](https://github.com/mango6i) · [MIT License](LICENSE)

> **使用前请了解：**恢复检查需要提前建立原生排程。如果额度耗尽时尚未建立排程，无法保证自动唤醒。完整的额度耗尽、刷新、唤醒与发送周期仍待验证，后续额度周期也需正确重新排程。

## 功能

- **统一设置**：保存一次即可管理阈值、刷新后的等待时长和多行提示词。
- **本地额度检测**：插件服务连接期间只读查询额度，空闲时也可检测，不使用模型每分钟轮询。
- **目标对话保持专注**：检测脚本只记录数据，不向工作对话注入插件指令，也不拦住任务结束。恢复排程由控制对话处理。
- **实际刷新时间**：显示账号接口返回的五小时额度刷新时间，以及加上等待时长后的预计复查时间。
- **对话管理**：搜索、刷新、勾选、全选当前列表及清空选择。
- **恢复排程校验**：额度尚可用时提前安排检查，核对客户端实际触发时间，防止名义时间正确但提前唤醒；漏检与暂停会单独提示。
- **清楚的状态**：分开显示已选对话、候选数量、最近检测、任务事件及实际检查时间。
- **发送前复查**：确认额度恢复、等待时间已到，且同一轮被记录的任务明确因本次额度耗尽停止；旧失败、设置请求和结果不明的发送不会重放。

## Tibo 重置公告与全量重置停任务

独立功能会读取 [@thsottiaux](https://x.com/thsottiaux) 的新原创帖。正文包含设置中的关键词（默认 `reset`，不区分英文大小写）时，向全部符合条件的本地根对话发起项目检查，不受原续接勾选范围限制。旧帖、转发和引用内容不触发；同一帖子每个对话最多发送一次。

- **自定义关键词**：可填写单个词或短语，按普通文字匹配，不使用正则表达式。换词仅影响保存后发布的新帖，不补发历史帖，已有发送记录继续去重。
- **自定义指令**：默认 `请帮我全量检查此项目是否还有可以优化的地方，隐藏的问题，修复好`，保留空格和换行。
- **执行模型**：GPT-6 Astra「极高」（`gpt-6-astra` / `xhigh`）；账号不可用时不会替换成其他模型。
- **运行中对话**：稍后处理。等待输入或批准、暂停、归档、远程、子代理及控制对话会排除；已完成项目可以发起新一轮检查。
- **额度全部重置**：实际五小时和每周剩余额度同时变为 100%，且刷新时间向前推进时，停止全部仍运行的本地项目轮次，取消尚未发送的检查和旧续接候选。控制对话除外。首次读到满额度不会误停任务；已经消耗的额度不会退回。
- **结果确认**：只有原生轮次变成 `interrupted` 才显示已停止。发送或停止结果不确定时不自动重试，停止未确认期间不再启动项目检查。手动核实任务后，可关闭并重新开启新功能以解除待处理状态。

**兼容性要求：**本功能需要客户端开放可验证的原生共享任务控制通道，并支持所选模型。插件会在每台电脑上单独检查，仅通过 `codex app-server proxy` 连接现有服务，不另建服务、不开启远程控制。缺少接口时阻止启用并说明原因。目前并非所有桌面版本都提供此接口，检测成功不等于自动操作已经就绪。

插件服务连接期间，默认每 5 分钟只读检测一次公开首页；额度与停任务检查使用已保存间隔，默认 60 秒。实际检测和停止有轮询、网络延迟，不保证精确到秒。客户端和设备需要保持运行；只读检查不调用模型，发起项目检查会使用正常额度。

### 开启方式

1. 在本机初始化一个控制对话，按下文审核并信任脚本。
2. 点击 **检查公告与兼容性**，此操作不会发送消息或停止任务。
3. 填写公告关键词、检查指令和公告检查间隔。关键词默认 `reset`，可先单独保存；“检查公告与兼容性”也可预览尚未保存的关键词，不触发群发。
4. 在公告一行的最右侧开启 **公告检查与重置停任务**，保存后生效。不支持的客户端会拒绝启用，整批设置保持原值，开关回到实际保存状态。该限制不是插件中的权限开关，无法在此页面强行打开；关键词和指令仍可单独保存。

## 安装

需要 **Windows、Python 3.10+、Codex CLI**，以及支持本地插件的 Codex / ChatGPT Work 客户端。

1. 从 [Releases](https://github.com/mango6i/codex-task-resume/releases) 下载 `codex-task-resume-1.0.zip` 并解压。
2. 完全退出客户端，运行解压目录中的 `install.cmd`。
3. 安装成功后重新打开客户端。
4. 在插件详情的 **设置 → 统一管理** 中点击 **管理 Codex 任务续接**，或使用应用入口 **Codex 任务续接 · 管理**。

也可以把 ZIP 附给能访问本机文件的本地 Codex / ChatGPT Work，使用[安装提示词](docs/INSTALL_WITH_CODEX.md)。这个包使用本地安装器；GitHub 自动生成的 Source code 压缩包与发行安装包不同。

## 快速使用

1. 在一个保留的本地控制对话中初始化一次：

   ```text
   使用 $quota-resume 初始化设置，保留我已保存的参数，暂不开启自动续接。
   ```

2. 按客户端原生提示审核并信任插件的检测脚本。
3. 在设置面板中填写参数，明确开启自动续接并保存。
4. 在对话管理中选择范围和目标，点击 **保存选择**。
5. 在额度仍可用时，让控制对话建立原生恢复检查，并确认排程状态。

参数和目标都在面板中统一修改，不需要在每个目标对话重复初始化。

已建立的原生恢复排程在后台执行，无需把控制对话置于前台，也无需打开管理面板。客户端和设备仍需运行。插件服务负责只读检测，不能独立创建原生排程或直接发送消息；首次排程与后续重新排程仍需要可用的原生助手能力。

“仅预排检查”表示提前安排了控制端检查，不表示已达到低额度条件或已发送续接消息。记录候选仍要求剩余额度严格低于所设阈值。若控制端无法自动唤醒，检测记录会保留，但不会借用其他项目对话执行排程。

## 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 剩余额度阈值 | 2% | 五小时额度严格低于此值时记录候选；范围 0.01–99% |
| 刷新后等待 | 2 分钟 | 实际刷新时间之后等待再复查；范围 1–60 分钟 |
| 续接提示词 | `继续任务` | 按保存的原文发送，保留换行 |
| 检测最短间隔 | 60 秒 | 插件服务与任务事件共用查询节流 |
| 自动续接 | 关闭 | 初始化并审核脚本后，由用户明确开启 |

例如，实际刷新时间为 19:13，等待 2 分钟，最早可复查时间为 19:15。客户端排程可能提前或延后触发，插件会为名义排程预留时间并核验实际唤醒不早于 19:15，因此实际检查可能更晚，以面板为准。无法核验时不会标记为就绪；绿色确认中的时间是设置保存时间。

## 语言

项目首页默认显示中文，可从顶部切换到英文说明。插件界面跟随 Windows 显示语言：中文系统显示简体中文，其他语言显示 English。系统语言改变后重新打开面板即可。

对话标题、项目路径、保存的提示词及换行保持原文。

## 常见问题

**已选多个对话，为什么候选仍为 0？** 选择仅限定允许处理的范围，不会直接入队或启动对话。只有本轮低额度时实际运行、并被绑定具体任务轮次的工作才会记录。候选与已建立的排程也分别显示。

**“回合已结束”是否表示任务完成？** 这里只表示最近一次任务事件。发送前仍需检查原生状态和上下文；完成、仍运行、暂停、等待输入或批准、归档及状态不明的任务会跳过。

**刷新额度失败怎么办？** 查询会重试一次。若有近期成功数据，会明确标注为历史数据；否则显示暂未获取，可稍后重试。历史显示不会作为发送依据。

**是否消耗额度？** 设置读写与本地只读额度查询不调用模型；建立排程、恢复检查和继续执行任务使用正常额度。

**客户端关闭后还能运行吗？** 插件服务断开或设备休眠后无法继续本地检测，恢复执行可能延后。普通 ChatGPT 网页、云端任务、远程主机及子代理不受支持。

**如何停止？** 关闭自动续接开关并保存。要同时暂停已建立的检查，在控制对话发送：`使用 $quota-resume 停止监控和自动续接。`

## 数据与隐私

设置和运行记录保存在本机 `%LOCALAPPDATA%/SkillHubQuotaResume/`。更新保留已有设置、选择、队列和发送记录。源码与发行包不包含实际用户设置、账号关联、任务队列或私人对话。

这是第三方本地插件。界面截图使用示例数据；反馈问题时请遮住个人对话、路径和账号信息。
